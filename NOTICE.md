# Runtime and source distribution

Selection translation reuses the user-owned PDF AI production Bing session, dictionary, citation normalization and translation implementation. Complete snapshot and license are supplied in `vendor/selection-translation/source/` and `COPYING`; `scripts/build-translation.mjs` builds the Bing-only runtime without CLI or model providers. The TypeScript adapter adds Google webpage translation and private MCP result delivery. The original Zotero selection popup is retained, with stale request cleanup and memoized translator registration for settings changes.

Complete corresponding integration sources, imported snapshots and component notices are included in this repository and in the complete GitHub release package. Source paths mentioned below refer to these included directories; no historical companion ZIP is required. See `SOURCE-BUNDLE.md`.

# Third-party reader and source

Workspace books use the official Spell UI PerspectiveBook React component (MIT), installed from its shadcn registry. Integration controls use official Lucide SVG nodes (ISC); Zotero's original reader icons are retained. Source and UI/fonts provenance are documented in `vendor/workspace-ui/PORTING.md`, with corresponding licenses in that folder. React and ReactDOM (MIT) provide the book component islands; Tailwind (MIT), clsx (MIT) and tailwind-merge (MIT) supply its local styles and class utility.

MinerU integration reuses the owner's `pdf-ai/electron` conversion client, layout normalizer, content tree, native outline merger, and the PDF project's pure coordinate mapping functions. Unmodified source snapshots and SHA-256 provenance are supplied in `vendor/mineru/source/` and `vendor/mineru/PROVENANCE.json`; derived mapping and runtime-path adapters are regenerated by `scripts/build-mineru.mjs`. TypeScript orchestration, private MCP tools, worker lifecycle, and the collapsible UI are in `src/server/mineru*.ts`, `src/shared/mineru.ts`, and `src/ui/mineru-panel.ts`. The original Server remains separately running, with its existing authentication, upstream and usage-settlement behavior. No Server database or secrets are shipped. ZIP reading uses yauzl (MIT); image composition uses @napi-rs/canvas (MIT), with Windows x64 binaries and their package licenses included under the MinerU runtime. The owner's imported modules retain the supplied source license.

This plugin includes the full Zotero Reader and the Zotero PDF.js fork from the user's `pdf-ai` project. This is an independent integration; Zotero is not its publisher.

- Reader repository: https://github.com/zotero/reader
- Reader base commit: `439a43d3fe1f56729bcd85fbfdf4d8b7ba0c76d9`
- PDF.js repository: https://github.com/zotero/pdf.js
- PDF.js base commit: `b0d511c4947bc32127bd7aa1a2b834e3bd0baa64`
- The reference project has local modifications, including its text selection and annotation selection bridge. The actual imported snapshot, rather than a clean upstream checkout, is supplied in `vendor/zotero-reader/source/`.
- Zotero Reader license: GNU AGPL version 3. See `vendor/zotero-reader/COPYING`. The plugin integration source is supplied under AGPL-3.0-or-later.
- PDF.js and bundled asset notices are in `vendor/zotero-reader/runtime/pdf/LICENSE/` and the corresponding source tree. Those third-party components retain their own licenses.
- Reader runtime provenance and the original `reader.js` SHA-256 are recorded in `vendor/zotero-reader/PROVENANCE.json`.

Integration modifications are in `src/ui/reader-adapter.ts`, `src/ui/viewer-local.ts`, `src/ui/pdf.ts`, and `src/server/pdf-*.ts`. `scripts/build.mjs` and `scripts/build-reader.mjs` supply an iframe message guard, per-document session token, save-flush handshake, local error reporting, and the reader HTML entry points. The imported reader.js, reader.css and PDF.js files are preserved. The derived `reader-local.html` replaces the Reader's nested HTTP navigation with srcdoc, removes a relative-directory URL assumption incompatible with srcdoc, routes messages through the session bridge, bundles the PDF.js viewer and in-page worker, and embeds CSS assets, CMaps, fonts and codecs. PDF.js resource factories are supplied by the TypeScript integration, and its image decoder fallback is embedded. Reader HTML hides reference-project AI analysis, whole-document translation and remote voice controls whose backends are not part of this plugin.

The Day and Night built-in themes and host color mapping are implemented in `src/ui/reader-theme.ts` and `src/ui/reader-theme.css`. The derived runtime replaces the native theme registry and appearance controls with two interface schemes and independent white/black paper controls. Saved preferences take precedence over host mode notifications. Matching host palettes are used where available; PDF pages use Zotero's existing theme renderer, retaining annotation colors and its image handling. The derived runtime also guards selection mapping while text nodes are unavailable and skips PDF page resets when effective paper rendering settings have not changed. These patches are maintained in `scripts/build-reader.mjs`; the imported upstream runtime remains intact.

The file management toolbar button is added to the derived Reader bundle by `scripts/build-reader.mjs`. PDF export uses the unmodified Zotero PDF worker imported from the reference project, base commit `024339a8469d7af368b9580b85fd8c8e906384bb`, with its PDF.js commit `91f87bb4c2d3cf9eb9e8604863e5c62509dfbbed`. Its AGPL-3.0 license, source, build scripts and runtime provenance are supplied under `vendor/pdf-worker/`; the PDF.js and font components retain their original notices. `src/server/pdf-export-worker.ts` calls `writeAnnotations` in a Node worker thread with local asset providers. The integration returns a new PDF through private MCP chunks and the host download interface.

`scripts/vendor-reader.mjs <pdf-ai-project>` imports the runtime and corresponding modified project source. npm build regenerates the TypeScript integration and reader entry point. Rebuilding the upstream reader itself uses the included upstream build configuration, pinned package lock and source submodules; dependency installations and upstream test/example files are not bundled.

The former Markdown snapshot editor was removed in 0.10.1; native whiteboard notes now use Milkdown/Crepe and ProseMirror for both editing and static rendering. The original Source Han Serif font remains in use by the PDF workspace with its corresponding notices.

KaTeX is bundled solely for local formula-card HTML and accessible MathML rendering with embedded WOFF2 fonts (MIT). See vendor/workspace-ui/LICENSE-KaTeX.

## Native note editor (0.13.40)

Milkdown/Crepe, ProseMirror, Mermaid, CodeMirror and Lezer are bundled locally under their MIT licenses. DOMPurify is used under its Apache-2.0 option to sanitize inline and block HTML. HTML code fences remain source-only. Component license texts are in `vendor/note-editor/licenses/`. Lucide provides the table grips and alignment controls; existing Lucide notices continue to apply. Integration adapters and note extensions are supplied in `scripts/milkdown-slash.mjs` and `src/whiteboard/note-*.ts`; dependency versions are pinned in `package-lock.json`.
